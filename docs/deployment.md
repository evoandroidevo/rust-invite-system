# Deployment

The container build is split into a Rust builder stage and a smaller runtime stage. The runtime image runs as a dedicated non-root user and expects the application to use a writable `/app/data` volume for SQLite.

## Start

The root [docker-compose.yml](../docker-compose.yml) starts the app on an internal network and publishes only the reverse proxy. The app itself is not exposed directly on a host port.

The CI workflow publishes the built image to GitHub Container Registry as `ghcr.io/<owner>/<repo>` on pushes to `main` and version tags.

Versioning follows SemVer from `Cargo.toml`. Release artifacts should be tagged `vX.Y.Z`, and the published image should receive both `vX.Y.Z` and `X.Y.Z` tags in GHCR.

Tag pushes also create a GitHub Release with autogenerated notes.

Required runtime inputs:

- `APP_LDAP_HTTP_URL`
- `APP_LDAP_LDAP_URL`
- `APP_LDAP_BASE_DN`
- `APP_LDAP_USERNAME`
- `APP_LDAP_PASSWORD`
- `CADDY_ADMIN_PASSWORD_HASH`

Optional LDAP TLS inputs:

- `APP_LDAP_USE_TLS`
- `APP_LDAP_TLS_INSECURE_SKIP_VERIFY`
- `APP_LDAP_TLS_CA_FILE` if you add it to your local config override or an orchestrator-specific secret file

## Secrets

Keep the LDAP bind password and proxy password hash out of committed files. Use environment injection from your orchestrator, a local `.env` file that is ignored by Git, or a secrets manager.

The database file lives in the `app-data` volume. If you need to rotate the LDAP password, update the secret value and recreate only the app container.

## Backups

Back up the SQLite database by stopping the app or taking a filesystem snapshot of the `app-data` volume, then copy the database file out of the mounted volume. Back up the config file and any proxy certificates separately.

## Upgrades

To upgrade, build or pull the new image, recreate the `app` service, and verify that migrations succeed on startup. If you also change the proxy config, recreate the proxy service after validating the certificate and admin-auth settings.

## Recovery

To recover, restore the SQLite volume snapshot, restore the config and cert files, then restart the proxy and app services in that order. If the database restore came from a previous version, run the service once and confirm migrations complete before resuming normal traffic.
